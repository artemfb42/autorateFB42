# АвтоРейт — Sprint 2: Аудит вимог і стратегія тестування

**Продукт:** АвтоРейт (AutoRate)  
**Спринт:** 2 / W4–W5  
**Базова специфікація:** [SRS 1.0 — навчальна реконструкція](SRS-1.0-reconstructed.md) (**не документ, виданий викладачем**)  
**Редакція інкременту:** 13.10.2026

## Походження базової SRS

У каталозі продукту П5 згадується `SRS_05_АвтоРейт.html`, але команді його не було передано. `SRS-1.0-reconstructed.md` — підготовлена для навчальної роботи реконструкція на основі каталогу та попередніх робочих описів. Реєстр RD і diff коректні **відносно цієї базової редакції**, але вони не є доказом аудиту справжньої специфікації замовника чи знаходження всіх прихованих дефектів. Якщо викладач надасть офіційний файл, зіставлення потрібно повторити.

## Результат спринту

Підготовлено комплект документів для аудиту специфікації та планування тестування: реєстр із 26 технічно описаними дефектами вимог для командної звірки, редакцію SRS 1.1 з журналом змін і повним diff, план тестування зі всіма 7 рівнями й аналізом 24 типів, завдання команди, опонування, сценарій Demo й матеріали ретроспективи.

## Змістовні результати

- **26 описаних проблем реконструйованої SRS:** 4 неоднозначності, 5 неповнот, 6 суперечностей, 3 проблеми простежуваності, 4 нездійсненні вимоги, 4 нетестопридатні формулювання.
- **7 рівнів тестування:** від unit та integration до customer acceptance.
- **24 типи проаналізовано:** 17 релевантних, 4 умовних, 3 незастосовних із поясненнями.
- **Ризики продукту:** один голос на модель, узгодженість рейтингу, модерація коментарів, Unicode, доступ до профілю, поведінка після Logout.

## Як підтверджується командний процес

Особисті результати кожного учасника розміщуються в [independent-audit/](independent-audit/README.md); письмові оцінки — у `peer-review/`. Записи про фактичних авторів RD, протокол зустрічі та погодження замовника оформлюються відповідальними учасниками. **Наявність готових документів не замінює підписів або проведених командою подій.**

## Контроль перед захистом

1. Звірити Excel і Markdown-реєстр, ID та кількість RD.
2. Підтвердити авторів незалежних знахідок і фактичні рішення щодо спірних пунктів.
3. Перевірити, що кожне виправлення SRS 1.1 має запис у diff і RD.
4. Показати 7 рівнів, ≥15 типів, конкретні цілі та описи на Demo.
5. Завершити живу таблицю задач, провести Retro й оформити peer-review за фактом.
