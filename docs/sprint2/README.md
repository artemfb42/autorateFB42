# АвтоРейт — Sprint 2 «Аудит вимог і стратегія тестування»

**Продукт:** АвтоРейт (AutoRate)  
**Спринт:** 2 (W4–W5)  
**Команда:** 5 учасників  
**Базова специфікація:** [SRS 1.0 «АвтоРейт»](SRS_05_АвтоРейт.pdf)  
**Мета:** аудит вимог та розробка стратегії тестування.

## 1. Мета спринту

Перевірити якість вимог SRS 1.0 за шістьма критеріями, сформувати реєстр дефектів, підготувати виправлену специфікацію SRS 1.1 та визначити план тестування програмного продукту.

### Критерії якості вимог

1. Однозначність.
2. Повнота.
3. Несуперечливість.
4. Простежуваність.
5. Здійсненність.
6. Тестопридатність.

### Нормативи для команди з 5 осіб

- Не менше 20 підтверджених дефектів вимог.
- Не менше 2 дефектів на кожен критерій.
- Усі 7 рівнів тестування.
- Не менше 15 типів тестування.
- Незалежний аудит кожного розділу щонайменше двома учасниками.

## 5. Підсумок аналізу вимог

У реєстрі описано 28 проблем вимог, розподілених за критеріями:

| Критерій | Кількість |
|---|---:|
| Однозначність | 5 |
| Повнота | 5 |
| Несуперечливість | 7 |
| Простежуваність | 3 |
| Здійсненність | 4 |
| Тестопридатність | 4 |
| **Разом** | **28** |

Окреме **питання Q-01 (кандидат RD-29, не включений до 28 дефектів)** стосується джерела оцінки 1–5 та репутації користувача для розрахунку зваженого рейтингу. Воно наведене в `requirements-defects.md` та на аркуші «Спірні» Excel; рішення замовника очікується.

## 6. Стратегія тестування

План охоплює 7 рівнів і 24 типи тестування.

- 8 типів мають доступні зараз сценарії.
- 13 типів залежать від отримання Java-модуля або окремого тестового середовища.
- 3 типи визначено незастосовними для поточного обсягу продукту.

Публічний demo використовується лише для дозволених ручних перевірок. Тести Java-модуля заплановані для Sprint 4 після отримання вихідного коду.
