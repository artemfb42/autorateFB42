## 1. Вступ

### 1.1 Призначення
Специфікація описує функціональні, інтерфейсні, бізнес-логічні та нефункціональні вимоги до вебкаталогу «АвтоРейт». Служить основою для аудиту, тест-кейсів, модульних перевірок і простежуваності. Ідентифікатори F-, GUI-, BL-, P-, S-, U-, D- зберігаються.

### 1.2 Межі продукту
Вебзастосунок охоплює реєстрацію, вхід, сторінки марок і моделей, голосування з коментарем і профіль. Модуль `autorate-module` (Java 17) містить підрахунок рейтингів, перевірку голосів і пошук. Інтерфейс адміністратора каталогу, інтерфейс модератора і мобільний застосунок — поза обсягом версії 1.0.

### 1.3 Терміни

| Термін | Значення |
|---|---|
| Марка | Автовиробник із логотипом, описом та моделями. |
| Модель | Авто певної марки, для якого є фото, характеристики, голоси й коментарі. |
| Голос | Одна прийнята оцінка авторизованого користувача для однієї моделі. |
| Рейтинг | Оцінка від 0,0 до 5,0, отримана як зважене середнє з репутацією як вагою (BL-10). |
| Ранг | Порядок моделі за спаданням рейтингу з правилом рівності (BL-20); зміна щодо визначення через лише кількість голосів — потребує погодження. |
| Репутація | Ціла вага голосу від 1 до 3. |
| Стоп-список | Заборонені слова, які спричиняють відхилення коментаря. |
| Сеанс | Період дій користувача після входу до Logout або тайм-ауту неактивності. |

### 1.4 Джерела
- Каталог продуктів, розділ 7 «АвтоРейт».
- Демонстраційний вебсайт: https://buggy.justtestit.org
- SRS 1.0 «АвтоРейт», вересень 2026.
- `autorate-module` Java 17 / Maven, для перевірки точних контрактів.

## 2. Загальний опис

### 2.1 Ролі
- **Відвідувач:** перегляд каталогу, рейтингу, коментарів, реєстрація і вхід.
- **Авторизований користувач:** додатково голосування з коментарем, профіль, зміна пароля, вихід.
- **Модератор:** перегляд і приховування коментарів; відповідний UI поза версією 1.0.
- **Адміністратор каталогу:** додавання та зміна марок і моделей; відповідний UI поза версією 1.0.

### 2.2 Середовище
SPA, актуальні Chrome/Firefox на ПК з JavaScript. Публічне demo має спільні дані й не використовується для навантажувальних тестів або тестів підбору паролів. Бізнес-логіка — JDK 17, Maven 3.9, JUnit 5.

### 2.3 Обмеження
Мова UI — англійська; для тестів допускаються вигадані дані. Голосування лише після входу. Значення загальних лічильників на публічному demo змінюються іншими користувачами: перевірки не повинні вимагати абсолютної сталої величини. Максимум за припущенням — 1000 моделей і 100 марок.

## 5. Вимоги до бізнес-логіки

Класи: `RatingAggregator`, `VoteValidator`, `ModelSearch`; типи даних: `Vote(userId, modelId, rating, reputation, comment)` і `CarModel(make, name, rating, votes)`; пакет `ua.kpi.tzyapz.autorate`. Десяткові обчислення — `BigDecimal`, округлення до 0,1 `HALF_UP`, зовнішній результат — `double`; `null` замість колекції → `IllegalArgumentException` (як у SRS 1.0).

| ID | Пріоритет | Формулювання (проєкт) |
| --- | --- | --- |
| BL-10 | High | RatingAggregator.average(votes): зважене середнє rating (1–5) із reputation (1–3) як вагами; округлення до 0,1 HALF_UP. Порожній список дає 0,0; недопустима оцінка або вага → IllegalArgumentException. |
| BL-20 | High | RatingAggregator.topN(models,n): не більше n моделей за рейтингом спадно, однакові рейтинги — повна назва (make + name) за алфавітом без регістру; n≤0 → порожній список. Пропонований мінімум votes для включення — 3, узгоджується з F-130 після підтвердження. |
| BL-30 | High | VoteValidator.validate(...,existingVotes): за наявності тієї ж пари userId/modelId серед попередніх голосів повертається «повторний голос»; результат — список порушень, порожній список означає прийняття. |
| BL-40 | High | rating — ціле значення від 1 до 5; поза діапазоном — «оцінка поза межами 1..5». |
| BL-50 | High | comment після trim має містити 1–200 символів; null, порожній та пробільний відхиляються як обов’язковий коментар, понад 200 — «коментар задовгий». [Точний текст помилки для порожнього коментаря узгодити.] |
| BL-60 | Medium | ModelSearch.search(query,models): префіксний case-insensitive пошук за назвою марки або моделі після trim; порожній/пробільний query → порожній список, порядок збігається з порядком входу; підтримка довільної мови і fuzzy-помилок не гарантується в цьому модулі. |
| BL-70 | Medium | ModelSearch.sortByRating(models): новий список, сортування rating спадно, при рівних значеннях — повна назва make + name у регістронезалежному алфавітному порядку, вхідний список не змінюється. |
| BL-80 | High | VoteValidator перевіряє коментар на окремі слова зі стоп-списку без урахування регістру; стартовий словник spam, scam, casino, казино, дозволений власний через конструктор. Межі слова визначено за Unicode; збіг тільки частини довшого слова не відхиляється. Контракти винятків і невалідного вводу задаються відповідними BL-10/BL-30/BL-40/BL-50 та вступом до розділу 5. |

## 8. Порядок затвердження
1. Кожен учасник незалежно перевіряє призначені розділи вихідної SRS 1.0.
2. Тест-аналітик звіряє запропоновані RD-xx з незалежними знахідками, об’єднує дублікати і заповнює справжніх авторів.
3. Аудитор-опонент і керівник приймають або відхиляють кожну суперечливу пропозицію.
4. Замовник підтверджує відкриті пороги та бізнес-рішення.
5. Тест-аналітик залишає в SRS 1.1 лише затверджені правки; у журналі відмічає автора, дату й номер дефекту.

**Примітка:** викладені вище формулювання — ретельно підготовлений проєкт, а не фактичне погодження замовником.
