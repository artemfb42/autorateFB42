## 4. Статуси виконання

| Статус | Значення |
|---|---|
| **To Do** | Завдання заплановане, виконання ще не розпочато |
| **In Progress** | Виконавець працює над завданням |
| **Review** | Робота завершена та очікує рецензування |
| **Done** | Роботу перевірено, зауваження усунено, результат прийнято |
| **Blocked** | Виконання заблоковано через залежність або проблему |

## 5. Контроль якості — Scrum Master

Під час рецензування перевірити:

- [ ] У кожного дефекту вимоги вказано ID або точне місце вимоги без ID.
- [ ] Кожен дефект класифіковано за одним із шести критеріїв якості.
- [ ] Опис дефекту містить обґрунтування з посиланням на пункт чек-листа.
- [ ] Для кожного дефекту запропоновано конкретне виправлення.
- [ ] Вказано фактичного автора кожного знайденого дефекту.
- [ ] Виправлена SRS містить журнал змін із посиланнями на дефекти.
- [ ] План тестування охоплює всі 7 рівнів тестування.
- [ ] План містить щонайменше 15 типів тестування для команди з 5 осіб.
- [ ] Кожен застосовний рядок плану містить конкретні «Ціль» та «Опис».
- [ ] У плані наведено пріоритети, інструменти й тестові дані.
- [ ] Незастосовні типи тестування мають обґрунтування.
- [ ] Зауваження рецензування опрацьовані до Demo.
- [ ] Протокол ретроспективи оформлено та додано до репозиторію.
