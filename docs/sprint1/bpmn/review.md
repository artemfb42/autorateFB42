# Протокол рецензування BPMN-моделей
**Спринт №:** Спринт 1 «Продукт і вимоги»  
**Команда:** $Win   
**Продукт:** Онлайн-каталог автомобілів та медіа-платформа «АвтоРейт» (autorate)  
**Дата планування:** 16.09

## 1. Мета рецензування

Метою рецензування є перевірка BPMN-моделей продукту «АвтоРейт» на відповідність визначеному чек-листу, процесним описам та ролям учасників.

Під час рецензування перевіряється:

* правильність структури пулів і доріжок;
* наявність початкових і кінцевих подій;
* правильність використання потоків керування та повідомлень;
* коректність роботи шлюзів;
* відповідність назв елементів BPMN їхньому типу;
* відповідність ролей процесу;
* відсутність «висячих» елементів;
* відповідність моделі опису процесу та очікуванням замовника.

Після виявлення зауважень моделі були скориговані та повторно перевірені.

## 2. Об'єкт рецензування

| № | BPMN-модель | Процес   |  Основні учасники  |
| - | ----------- | -------- | ------------------ |
| 1 | Реєстрація і вхід  | Реєстрація нового користувача та авторизація зареєстрованого користувача | Відвідувач, Система   |
| 2 | Голосування за модель| Вибір автомобільної моделі, оцінювання та додавання коментаря | Зареєстрований користувач, Система |
| 3 | Модерація коментарів | Перевірка коментарів та обробка порушень | Модератор, Система |
| 4 | Додавання нової моделі в каталог | Створення та перевірка картки нової автомобільної моделі | Адміністратор каталогу, Система |

## 3. Чек-лист рецензування

| ID | Пункт чек-листу | Що перевіряється  |
| ----- | -------------| ----------------- |
| CL-01 | Початкові та кінцеві події | Кожен пул із власним процесом має хоча б одну Start Event та одну End Event. Start Event має тільки вихідний потік, End Event — тільки вхідний. |
| CL-02 | Зв'язність дій  | Кожна задача має хоча б один вхідний та один вихідний sequence flow. |
| CL-03 | Межі пулів | Sequence Flow не перетинає межі пулів. Для взаємодії між пулами використовується Message Flow. |
| CL-04 | Шлюзи | XOR/OR-шлюзи сформульовані як питання, а їхні вихідні гілки мають зрозумілі умови. |
| CL-05 | Злиття гілок | Розгалуження AND/OR коректно синхронізуються або кожна незалежна гілка завершується окремо. |
| CL-06 | Event-based Gateway | Після Event-based Gateway використовуються проміжні події, наприклад отримання повідомлення або таймер, а не звичайні задачі.|
| CL-07 | Назви елементів  | Задачі названі у формі «дія + об'єкт», події — як факт/стан, шлюзи — як питання. |
| CL-08 | Доріжки | Кожна доріжка має назву відповідно до ролі з легенди та містить хоча б одну задачу. |
| CL-09 | Артефакти та дані | Data Object має назву-іменник та приєднується до задачі Association, а не Sequence Flow.|
| CL-10 | Читабельність і відповідність процесу | Модель читається зліва направо, не має зайвих перетинів та відповідає опису процесу, ролям і результатам. |
