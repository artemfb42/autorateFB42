## 3. Обсяг і підхід

Ручне функціональне тестування demo: реєстрація, авторизація, каталог, рейтинг, голосування, коментарі, профіль, базові UI-перевірки. Перевірки виконувалися за SRS 1.1, із використанням позитивних та негативних сценаріїв, класів еквівалентності й аналізу граничних значень. Сторонні API, внутрішні бази даних, навантажувальне та кодове тестування не входили до фактично доведеного ручного прогону.

## 8. Ризики і приймальний контроль КТ

- **R-01, критичний документальний:** немає окремого перевіреного рішення замовника про зміну числових меж; деталі у [реєстрі](../sprint2/requirements-decisions-sprint3.md).
- **R-02:** зміна оракула після тестування для TC-036/038 створює ризик викривлення статусів.
- **R-03:** BUG-012 залежить від бізнес-погодження довжини Phone.
- **R-04:** перед прийманням звірити 100% незалежних Review (TC та Issues), мітки GitHub і релевантність доказів.
- **R-05:** на публічному demo невідомі внутрішні механізми модерації, API, БД та окремі нефункціональні вимоги.

## 9. Definition of Done

| Критерій | Висновок КТ |
|---|---|
| ≥25 TC | Виконано: 45 |
| Виконано 100% TC | Виконано: 45/45 |
| ≥10 Issues, ≥3 Severity | Виконано за кількістю: 13, 3 рівні |
| Відтворення 3 дефектів різних Severity | Задокументовано в audit.md |
| 100% підтвердженого peer review | Перевірити фактичні авторські записи; сам текст `approved` не достатній |
| Шаблон, мітки, трекер | Шаблон є, мітки необхідно перевірити в GitHub |
| Ретроспектива | Протокол має відображати проведену зустріч, не тільки заповнений шаблон |
| Єдина погоджена SRS | Частина значень потребує рішення замовника |

**Висновок КТ:** підготовлено значний доказовий інкремент і досягнуто кількісних цілей. Рішення «безумовно готово до здачі» залежить від закриття наведених документальних питань; розходження не приховано.
